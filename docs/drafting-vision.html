Product thesis

Not more chrome.
More confidence.

Rhino’s command line is powerful, but documentation work becomes a hunt through layouts, properties, dialogs, and remembered commands. Serpentine3D can keep the speed and remove the uncertainty.

01 / DIRECT

Act on what is selected.

A detail exposes scale and filters. A dimension exposes precision and its source. Text edits in place. The interface follows the object instead of making the user find the right dialog.

02 / LIVE

Show what is safe.

Views and annotations visibly report whether they are current, rebuilding, ambiguous, or broken. A blank view can never masquerade as a finished drawing.

03 / ONE ENGINE

Manual and headless agree.

The UI, scripts, MCP, CI, and AI all operate on the same drawing graph. A published sheet never depends on which viewport happened to be open.

A better interface than Rhino

One workspace.
Three levels of intent.

The navigator answers “where am I?”, the canvas answers “what am I changing?”, and the inspector answers “what exactly is it?”. The command line remains available without carrying the whole burden of discoverability.

Less hunting.
More drawing.

These are not separate modes or plugins. They are small, composable improvements to the work professionals repeat all day.

Sheets, views, health, issue state, and standards live in one navigator. A warning belongs beside the affected item—not in a log after export.

The first decisive acceptance test
Build an inch-based model, create an A3 sheet and a 1:10 view, associate a dimension, revise the model, verify the dimension, and export PDF—without constructing a GUI window.

Make scale undeniable

One conversion service defines model units, paper millimetres, view scale, dimension formatting, and scale bars.

Give references identity

Start with linear dimensions and a clear healthy / ambiguous / broken lifecycle.

Extract the drawing service

Create and render sheets through a document API independent of active Qt viewports.

Expose the same operations

Commands, the inspector, scripts, and MCP become adapters over one typed service.

Publish only known-good work

Golden outputs and preflight turn professional dependability into something testable.
