# AI / MCP integration

Serpentine3D ships an [MCP](https://modelcontextprotocol.io) server so AI
assistants can drive the modeller: create geometry, run any command,
inspect and screenshot the scene.

## In-app assistant

Open **Assistant** in the bottom workspace, then choose **Ask AI** beside the
shared input. **Command** returns to ordinary modelling commands. Each mode
keeps its own draft; opening a pane does not change the input destination.
The command history remains visible beside the conversation.

Choose your provider in **Settings → Assistant**.

### LM Studio: run a model on your machine

1. Open LM Studio and start its local server in the Developer view.
2. In Serpentine's Assistant settings, choose **LM Studio** and enter the
   server URL, usually `http://127.0.0.1:1234`.
3. Refresh the model list and choose a model. Qwen and Gemma can be used when
   installed in LM Studio; use a model trained for tool use to edit geometry.
4. Return to **Ask AI** and try: “Create a box 40 by 30 by 20.”

No Anthropic key is needed for LM Studio. Requests go to the server URL you
configure. With a loopback URL and a model served locally, inference stays
on this machine.

Model discovery uses LM Studio's capability information when available and
excludes embedding models. A vision model can inspect viewport screenshots;
a text-only model works with scene information and measurements. If the
server is unavailable or a model fails to load, the conversation shows the
error so you can correct the setup and retry.

LM Studio manages model loading, context size and CPU/GPU memory allocation.
If loading fails for lack of GPU memory, lower GPU offload or context size
there. Serpentine does not change those settings.

### Anthropic

Choose **Anthropic**, supply an API key, and select a model. You can also set
`ANTHROPIC_API_KEY` before launching the app. Anthropic requests send your
conversation and requested scene information to Anthropic's API; the key is
used only for that provider.

### Working alongside a drawing command

You can ask a question while a command is waiting for a point or another
answer. An AI action that conflicts with that command must wait until you
finish or cancel it. Switching input modes preserves your unfinished answer.

**Stop** cancels the current assistant turn. It does not undo geometry that
has already been created; use the usual Undo command for completed changes.
Changing models during a turn applies to the next turn.

## Connect an external MCP client

With the GUI running (it opens a local RPC bridge automatically), add
to your MCP client config — e.g. Claude Code:

```bash
claude mcp add serpentine3d -- /path/to/.venv/bin/serp3d-mcp
```

or in `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "serpentine3d": { "command": "/path/to/.venv/bin/serp3d-mcp" }
  }
}
```

The MCP server finds the running GUI through `~/.serpentine3d/rpc.port`.

## What the assistant can do

The server exposes these tools:

- `serp_create_curve`, `serp_create_surface`, `serp_boolean`,
  `serp_transform` — direct geometry with exact parameters
- `serp_command` — run **anything** a user could type, with scripted answers
  to its prompts
- `serp_scene_info`, `serp_measure`, `serp_screenshot` — see the scene (the
  screenshot returns an image of the viewport)
- `serp_select`, `serp_layers`, `serp_import`, `serp_export`, `serp_undo`,
  `serp_viewport` — selection, layers, files and the camera
- `serp_prepare_script` — open Python source as a new, unexecuted draft in
  the Script pane, ready for you to inspect and run

The combination of `serp_screenshot` and `serp_command` lets an assistant
inspect the current viewport and use the same modelling commands as you.
Geometry edits participate in the application's undo history. File exports
and other effects outside the document are not reversed by Undo.

External operations are labelled **MCP** in the common command history;
in-app assistant operations are labelled **AI**, and script runs **Script**.
MCP inspection remains available during a modelling prompt, while conflicting
edits report an error until you finish or cancel the command. Script handoff
preserves existing drafts and does not change the Command / Ask AI mode.

MCP is the interface for an external agent to control Serpentine. The
in-app assistant uses the same application operations and connects directly
to its selected model provider; it does not need a separate MCP client.

## The bridge

The running GUI opens a localhost-only JSON-RPC socket
(`~/.serpentine3d/rpc.port`); the MCP server (`serp3d-mcp`) connects to it. Set
`SERP3D_NO_RPC=1` to disable it.
