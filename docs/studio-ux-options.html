Recommended direction

Studio, with a compact command entry

Keep modeling spacious by default. Open Studio for sustained coding, then carry its scripts back into everyday modeling as reusable tools.

What this makes easier

Reading code while seeing its geometry. Moving from an AI-generated first pass to deliberate editing, parameters, examples, and reuse.

The tradeoff

Another workspace to learn. Preserve the same selection, document, activity, and undo behavior so the transition feels continuous.

Command or selection→Ask or write Python→Inspect geometry→Keep and revise→Save as a tool

One execution system

Commands, scripts, the built-in assistant, and external MCP clients should share scene operations and result reporting. Activity records inputs, outputs, source, and a useful undo boundary.

Local models are a normal choice

Settings select a provider, endpoint, and model. Serpentine runs the tool loop. Check each model’s tool and image capabilities; small models get focused tools and concise scene context.

Make a script worth keeping

Named inputs, parameters, owned outputs, and predictable reruns matter more than a large editor feature list. Bundle offline examples and let a working script become a named command.

Design exploration only. Layouts, geometry, run states, and model choices are simulated. Nothing executes Python, calls a model, or modifies a Serpentine document. The managed script API and preview lifecycle are proposals. This page is self-contained and uses no external assets or network services.
